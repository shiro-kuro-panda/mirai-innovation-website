# 夢の職業絵本メーカー（MirAI塾）

夢職業診断 → 絵本づくり → ビジネスモデルキャンバス までを、コピー＆ペーストなしで
1つのアプリの中で完結させるツールです。絵本は本文10ページ。

`index.html` を開くだけで動きます。ビルドもサーバーも要りません。

## なぜ Gemini Storybook を使っていないのか

Gemini アプリの Storybook は Gem（アプリ内機能）であり、**プログラムから呼び出せる公開APIがありません**。
そのため「アプリで生成したテキストを人がコピーして Storybook に貼る」という手作業が必ず発生します。

このアプリは Storybook を経由せず、**画像生成モデルを直接呼んで絵本の本文と挿絵をその場で生成**します。
これがコピペを不要にしている部分です。

## 全体の流れ

| ステップ | 内容 | 使うもの |
| --- | --- | --- |
| 1. 夢職業診断 | 5つの質問にチャットで答える | — |
| 2. 職業提案 | その子だけのオリジナル職業を提案 | Gemini（テキスト） |
| 3. 絵本づくり | 本文10ページ＋挿絵を生成し、めくり式で読む | テキスト＋画像モデル |
| 4. おしごとの せっけいず | ビジネスモデルキャンバス9マスに展開 | Gemini（テキスト） |

絵本と BMC は「印刷・PDF保存」からそのまま持ち帰れます。読み上げはブラウザの音声合成を使います。

10ページの流れは `PAGE_BEATS` で固定しています（紹介 → あこがれ → 一歩 → 小さな成功 →
壁 → 落ちこみ → 得意を思い出す → 乗りこえる → 花ひらく → 読者へのメッセージ）。
ページ数だけ増やすと話が冗長になるため、1ページ＝1つの出来事になるよう役割を決めています。

## 主人公の見た目をそろえる仕組み

挿絵をページごとに独立して生成すると、主人公の顔や服が毎ページ変わってしまいます。
そこで次の順で生成しています。

1. まず**キャラクター設定画**を1枚生成する（正面・横向き・顔アップの三面図、白背景）。これは表には出さず基準にだけ使う
2. **1ページめ**を設定画つきで生成する。これが画風の基準になる
3. **2ページめ以降**は「設定画 ＋ 1ページめ」の2枚を参照させ、**3枚ずつ並列で**生成する

10ページを1枚ずつ順番に描くと待ち時間が長すぎるため並列化していますが、
レート制限に当たらないよう同時実行数は3に制限しています（`IMAGE_CONCURRENCY`）。
表紙には1ページめの絵を使います。

## 挿絵の生成元（設定画面で選べます）

### Gemini（既定・サーバー不要）

| 画質 | モデル | 用途 |
| --- | --- | --- |
| 高画質 | `gemini-3-pro-image`（Nano Banana Pro） | 既定。2K出力、人物の同一性保持が最も安定 |
| 速度優先 | `gemini-3.1-flash-lite-image`（Nano Banana 2 Lite） | 速く安く仕上げたいとき |

`file://` で直接開いた場合でも、Gemini API 側が `Origin: null` を許可しているため CORS で弾かれません。

### gpt-image-2（プロキシが必要）

**OpenAI API は CORS ヘッダーを返さないため、ブラウザから `api.openai.com` を直接呼ぶことはできません。**
これは file:// でもホスティングしたページでも同じで、回避策はありません。使うには鍵を持つサーバーを1枚挟みます。

1. `proxy/openai-image.js` を Vercel の新規プロジェクトに `api/openai-image.js` として置いてデプロイ
2. 環境変数 `OPENAI_API_KEY` を設定（`PROXY_TOKEN` も設定を強く推奨。URLが漏れただけで課金され続けるのを防げます）
3. 設定画面で「gpt-image-2（プロキシ経由）」を選び、デプロイ先のURLと合言葉を入力

OpenAIのキーはプロキシ側の環境変数に置かれ、ブラウザには渡りません。
文章の生成には引き続き Gemini のキーを使います。

> `gpt-image-2` のリクエスト形式は実キーでの疎通確認をしていません（開発環境から
> `api.openai.com` と OpenAI のドキュメントの両方に到達できないため）。
> 形式が違っていた場合も、直すのは `proxy/openai-image.js` の `callOpenAI()` だけです。

## APIキーについて

初回に、画面右上の歯車から Gemini API キーを登録してください。
キーは <https://aistudio.google.com/apikey> で作成できます。

- キーは**その端末のブラウザ（localStorage）にのみ保存**され、Google 以外には送信されません
- 共用のパソコンで使った場合は、設定画面の「削除」を押してください
- キーを登録しなくても、診断と文章だけの絵本は動きます（挿絵とBMCはキーが必要です）

## モデルの選び方

モデルIDは提供側の都合で入れ替わります。そのためコード内で決め打ちせず、
**キーで実際に使えるモデルを `ListModels` で取得してから選ぶ**ようにしています。
設定画面の「使えるモデルを確認する」で一覧を取得し、手動で選ぶこともできます。

## 費用の目安

絵本1冊につき画像生成が**11枚**走ります（設定画1枚＋本文10ページ）。
Nano Banana Pro は 1K/2K で1枚あたり $0.134 なので、高画質だと1冊あたり **$1.5 前後**です。
速度優先に切り替えると大きく下がります。教室でまとめて使う場合は、
Google AI Studio 側で利用上限を設定しておくことをおすすめします。

## あとから文章側もサーバーに移す場合

ネットワークに触れているのは `callGemini()` / `listModels()` / `generateImageViaProxy()` の3つだけです。
一般公開して「利用者にキーを入力させたくない」場合は、この向き先を自前のAPIルートに変え、
キーの受け渡しを消すだけで移行できます。UI側の変更は不要です。
